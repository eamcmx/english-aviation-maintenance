Loading and verifying avionics software.

You are on the line with an avionics box open in the rack. The task card asks for a software load. In this unit you learn the words, the phrases and the grammar to load it, confirm every reference aloud, and prove the result is clean.

SpecialismAvionics & aircraft mechanics (EASA Part-66/145) FunctionFollow a software-load procedure and verify it Grammar focusSequence with once / when for stage gating Class length90 minutes · self-study ready

By the end of this unit you can …

  • Can follow a software-load procedure and confirm each step.
  • Can communicate part number, load number and configuration precisely.
  • Can verify a successful load or troubleshoot a failed one.

01The scenario

It is a day shift in the hangar. A comm radio on the aircraft needs new software, and the task card is signed out to you. Your job is a coordinated software load: one technician drives the dataloader, the other reads the references aloud and watches the screen. You confirm the part number, the load number and the load media before you start. When the bar reaches one hundred percent, the job is not done. You still have to verify the configuration, run the self-test, and write the result in the tech log. This unit walks you through the whole task in English, from the first reference to the last signature.

Dialogue 1

Starting the load

Transcript
ARight, today we are loading the latest software onto the number-two communication radio. Have you got the task card?
BYes, it is here. According to the task card, the software part number is 285-A047, revision C.
AGood. Let me read it back to confirm. Software part number 285-A047, revision C. Do you agree?
BConfirmed. The load number is L-2231, which matches the label printed on the load media.
AL-2231. Since the card and the media agree, we are authorised to begin the data load.
BThe LRU is the communication radio in rack two. Its part number is 622-1140-001.
ACorrect. Before loading, we must confirm compatibility, because this software runs on one hardware standard only.
BThe AMM task specifies mod 4 or later. I inspected the unit; it is mod 5, so we are compatible.
ANice catch. Now connect the dataloader to the front connector, and tell me once you have a link.
BThe dataloader is connected. I have a steady green link light, so the unit is communicating with the loader.
AOnce the link is stable, select the data load, although you must not start it yet.
BData load L-2231 is now selected on the display. It is waiting for my command to proceed.
AGood. When I say go, press start. As soon as it runs, monitor the progress bar alongside me.
BUnderstood. I will announce the percentage every twenty seconds, so that we both track it together.
APerfect. That way, if it halts unexpectedly, we notice immediately. Go ahead, press start now.
BStarted. Currently loading at four percent. The bar is advancing, and no fault message has appeared.
Dialogue 2

A failed load

Transcript
AHow is the load progressing now? You went quiet at sixty percent.
BIt has stopped. The display shows a checksum error, and the progress bar is completely frozen.
AA checksum error indicates that the data is corrupted. The dataloader cannot trust the file.
BSo either the load media is faulty, or the file copied incorrectly. What is our next action?
AWe abort this load immediately. Never leave a unit half-loaded. Press abort now.
BAborted. The display reads "load cancelled". Fortunately, the unit has retained its previous software.
AGood. A clean abort protects the existing configuration. Now we investigate the cause before we retry.
BShall I try the alternative load media? I have a second card carrying the identical file.
AYes, although you must check the label first. Unless the card matches exactly, do not use it.
BThe second card states load number L-2231, software part number 285-A047. It matches perfectly.
AThen swap the media and power cycle the loader, because a fresh start clears any memory fault.
BThe loader is off. I will wait ten seconds, then switch it on again, exactly as you taught me.
AGood. When it returns, reconnect and re-select the data load. Then read the checksum aloud to me.
BBack on. The checksum displayed is 4F-2A-91-D0, which matches the value on the task card.
AThe checksum is correct this time. That was a defective card, not a bad file. Restart the load.
BStarted. Sixty percent and still clean. It has passed the point where it previously failed.
Dialogue 3

Verify and sign off

Transcript
AThe bar has reached one hundred percent, and the display says load complete. Is that everything?
BNo. A finished bar is not a successful load yet, because we still have to verify it.
ACorrect. First, run the BITE test. The unit examines itself and reports any internal fault.
BBITE is running. Everything shows green, no faults, and the software block has passed.
AGood. Now open the configuration report, which lists exactly what the unit is currently running.
BThe configuration report shows software part number 285-A047, revision C, load L-2231.
ALet me cross-check that against the task card. I read 285-A047, revision C, load L-2231.
BConfirmed. The report and the card agree on every field, so the verification is complete.
ADo not forget the hardware line, because the report should also show the LRU part number.
BIt shows 622-1140-001, mod 5. That matches the physical unit, so compatibility is confirmed.
AExcellent. We now have a successful load, a clean BITE, and a fully matching configuration.
BShall I power cycle the unit once more, to prove that it boots reliably on the new software?
AYes. A final power cycle is good practice. Confirm that it returns without any fault.
BIt rebooted, ran BITE again, and remained green. The unit is completely healthy on the new load.
AThen we close the job. Record the load number and the result in the tech log.
BTech log updated. Communication radio two, load L-2231, verification complete, no faults found.

04Grammar in context, sequence with once and when

During a software load the sequence of operations is critical. You load initially, and afterwards you verify. English uses once, when and as soon as to gate one particular stage behind another. Examine these authentic lines taken directly from the dialogues:

"Once the link is stable, select the data load from the menu."
"When I say go, press start. As soon as it runs, watch the progress bar."
"Once the data load is complete, run BITE and open the configuration report."

The underlying pattern is straightforward. The once / when clause represents the gate, while the main clause specifies the subsequent action. Importantly, the gate uses the present tense, even though it clearly refers to the future. Consequently, you never use will inside the time clause.

PatternExampleWhen you use it
Once + past participle, + imperativeOnce loaded, verify the configuration.a short, passive stage gate
Once + subject + present, + imperativeOnce the load finishes, run BITE.a full clause with a subject
When + subject + present, + imperativeWhen the light turns green, press start.a trigger or a condition
As soon as + subject + present, + imperativeAs soon as it starts, watch the bar.the very next step, no delay

Three common mistakes (Latvian / Russian speakers)

1. Do not use will in the time clause.
✗ When the load will finish, verify the configuration.
✓ When the load finishes, verify the configuration.
Latvian and Russian mark the future in both clauses. English keeps the time clause in the present.
2. Do not drop the article the.
✗ Once configuration is verified, close job.
✓ Once the configuration is verified, close the job.
Latvian and Russian have no articles, so learners often leave the out. Put it back.
3. Do not drop the passive be.
✗ Once loaded the software, run BITE.
✓ Once the software is loaded, run BITE.
Use "is loaded", not "loaded the software". Keep the subject and the verb be.

E5 · Reading 1, Task card (AMM)

Read the task card. Then answer the six questions. Write short answers.

TASK CARD 34-52-11-720 · AMM REF 34-52-11 · SOFTWARE LOAD, COMM RADIO No.2

Zone: 121 (avionics rack, forward). Access: open panel 121AL. Warning: throughout this procedure the radio must receive power exclusively from the ground cart, never from the aircraft battery.

Step 1. Confirm the software part number 285-A047, revision C, and load number L-2231 on the load media. Whenever the media disagrees with the documentation, immediately raise a query.

Step 2. Confirm the LRU part number 622-1140-001 and verify the hardware standard is mod 4 or subsequent. Record the standard identified during inspection.

Step 3. Connect the dataloader to the forward connector. Once the link is stable, select data load L-2231 and press start. Do not interrupt the operation.

Step 4. Whenever a checksum error appears, abort the load, power cycle the loader, and retry with verified media. After two consecutive failures, quarantine the suspect media.

Step 5. Once the load is complete, run BITE and open the configuration report. Systematically cross-check the software part number and load number against this documentation. Enter the result in the tech log.

SERVICE BULLETIN SB 34-2231 · COMM RADIO 622-1140 · SOFTWARE UPGRADE TO L-2231

Reason: an intermittent fault occasionally causes the radio to lose the previous frequency following a power cycle. Software load L-2231 rectifies this behaviour. The upgrade is recommended, although not mandatory.

Effectivity: all communication radios bearing part number 622-1140-001 at hardware mod 4 or mod 5. Radios remaining at mod 3 are incompatible and must never be loaded.

Compliance: incorporate software part number 285-A047, revision C, at the next scheduled maintenance opportunity. The task requires approximately one hour, including complete verification.

Procedure: follow task card 34-52-11-720. Confirm the load media, execute the data load, then verify using BITE and the configuration report. Cross-check every field against the documentation.

Records: enter the load number and the revised configuration in the tech log. Retain the superseded configuration report with the aircraft records for twelve months.

06Speaking, role-plays

Work with a partner, or use the AI conversation partner below. Keep your sentences short. Read every reference aloud and confirm it, just like in the dialogues.

Role-play 1: Start the load

Situation A comm radio needs a software load. You have the task card and the load media.
Your role Lead technician (A).
Your goal Confirm the software part number, load number and compatibility, then start the data load.
Useful phrases "Let me read it back…" · "Do you confirm?" · "Once the link is stable, select the data load." · "When I say go, press start."

Role-play 2: Handle a failed load

Situation The load stops at sixty percent with a checksum error.
Your role Assistant technician (B).
Your goal Abort safely, find the cause, and agree a retry with your partner.
Useful phrases "The screen shows a checksum error." · "Should I abort?" · "Unless the card matches, I will not use it." · "Let me power cycle the loader."

Role-play 3: Verify and sign off

Situation The load reached one hundred percent. You must prove it is a successful load.
Your role Lead technician (A).
Your goal Run BITE, open the configuration report, cross-check every field, and close the tech log.
Useful phrases "First, run the BITE test." · "Let me cross-check that against the task card." · "The report and the card agree." · "Verification complete."

Role-play 4: Shift handover

Situation Your shift ends. A load on aircraft nine is only half done.
Your role Off-going technician.
Your goal Hand over clearly: what is done, what is left, and which references to check.
Useful phrases "The task card is on the bench." · "Please check the load media before you start." · "Once the data load is complete, run BITE." · "When you have a successful load, call me."

07Writing, a tech-log entry in Simplified Technical English

Write the tech-log entry for the software load you did in the dialogues. Use ASD-STE100 Simplified Technical English habits: short sentences (no more than 20 words), one instruction per sentence, the active voice, and approved words. Do not use two words when one is enough.

Your task

Write a tech-log entry of 60–90 words. Include: the unit and its part number, the software part number and load number, the steps you did, the BITE result, and the verification result. End with your name and the date.

STE tips: write "Run BITE", not "It is necessary to carry out a BITE test". Write "the load is complete", not "the loading procedure has been finalised". Keep each sentence to one idea.
