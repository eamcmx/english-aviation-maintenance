Interpreting a BITE readout with a colleague

A fault code appears on the flight deck, and two technicians read it aloud together. What system does the code name? Which line replaceable unit is the suspect? They map the fixed logic of the BITE message, and then they agree which unit to test first.

By the end of this unit you can …

  • Can read a BITE fault code and explain its meaning to a colleague.
  • Can relate a fault message to the affected system and LRU.
  • Can decide with a partner the follow-up action from the readout.

00The scenario

You are on the flight deck with a colleague, and the BITE has stored a fault from the last flight. Neither technician can act until you both understand the message correctly, because a fault code is only useful once you interpret it properly. Initially you identify the system from the ATA chapter, and afterwards you identify the suspect LRU. You never remove a serviceable unit at random, because that unnecessarily wastes valuable time and a good component. Instead, you calmly agree together which particular unit to test first.

A BITE readout follows fixed, predictable logic, so the identical code always maps to the identical meaning. The first digits give the ATA chapter, which accurately identifies the affected system. The fault message then identifies the LRU, which is the component you replace directly on the line. Because the logic is completely fixed, English uses the zero conditional to describe it, and you say plainly “if the BITE shows 34, the system is navigation”. Throughout this unit you read authentic fault codes aloud, explain them clearly to a colleague, and confidently decide the follow-up action together.

DIALOGUE 1 Read the code, name the LRU

Transcript

AWe are finally on the flight deck, so let us read the BITE readout aloud together.

BCertainly. The BITE currently shows one fault message, and the fault code is 34-12-34.

AIf the code starts with 34, the system is navigation, because 34 is the ATA chapter.

BExactly. So this maintenance message clearly points to navigation, not to the autoflight system.

AThe readout also identifies the LRU precisely. It says ADIRU 1, so the suspect unit is obvious.

BCorrect. If the BITE names ADIRU 1, the affected LRU is the number one air data unit.

ALet me run the self-test again immediately, in case the fault is merely intermittent.

BSensible idea. If the self-test passes, the readout shows no fault found, and we stop.

AUnfortunately the self-test still shows the identical fault code, so the fault is genuine.

BThen we confirm the message, and afterwards we open the CMC to examine the complete history.

AThe CMC lists the identical fault three separate times today, so the ADIRU is obviously faulty.

BAgreed. If the CMC repeats the code, the fault is confirmed, and the LRU becomes suspect.

ASo which unit do we test first? Personally I say ADIRU 1, because the readout names it.

BI completely agree. We isolate ADIRU 1 first, although we still inspect its connector carefully.

ASensible plan. If the connector is loose, we reset the unit before we remove anything.

BFine. As soon as the test is finished, we accurately record the result and the fault code.

DIALOGUE 2 An intermittent autoflight fault

Transcript

AOn the last flight the crew observed an ECAM warning for the autoflight system.

BLet us examine the BITE carefully, because the ECAM warning and the fault code should match.

AThe BITE fault code is 22-83, so the system is autoflight and the suspect LRU is FMGC 2.

BIf the code contains ATA 22, the system is autoflight, and 22 always indicates that chapter.

AThe fault message reads FMGC 2 FAULT, so the number two computer is obviously the suspect LRU.

BWe should run a ground test initially, because a ground test can safely repeat the fault.

APrecisely. If the ground test repeats the code, we confirm the fault and begin fault isolation.

BUnfortunately the ground test runs clean, and the readout currently says no fault found.

ASo the fault is clearly intermittent, because it appears in flight but hides on the ground.

BThat is genuinely the hardest kind. If the fault is intermittent, the CMC history still helps.

AThe CMC shows the identical fault code on three separate flights, so the LRU remains suspect.

BThen we certainly do not clear it yet, although the ground test currently looks perfectly fine.

ALet me inspect the connector and the rack, in case a loose pin causes the intermittent fault.

BSensible. If the connector is clean, we fit a serviceable FMGC 2 and monitor it carefully.

AAgreed. We isolate the fault to FMGC 2, and afterwards we test it on the next flight.

BFine. I accurately record the fault code, the ground test, and the follow-up action in the log.

DIALOGUE 3 A flight-controls code — agree the action

Transcript

AHere is a fresh BITE readout, and the fault code is 27-93, on the flight controls system.

BIf the code starts with 27, the system is flight controls, so this is definitely not navigation.

AThe fault message names ELAC 1, so the suspect LRU is the number one flight-control computer.

BLet me read the entire readout aloud, because the class of the fault clearly changes the action.

AIt says ELAC 1 FAULT, class 2, so we may defer it, although we still isolate the unit.

BGood. Initially we run the self-test, in case the fault clears after a normal reset.

AThe self-test unfortunately shows the identical fault code, so a simple reset does not fix it.

BThen we reset the ELAC once, and we carefully watch the readout for any change.

AAfter the reset the BITE still shows 27-93, so the fault is genuine and the LRU is suspect.

BAgreed. If the reset does not clear the code, we isolate ELAC 1 and inspect its connector.

AThe connector looks perfectly clean and tight, however, so the wiring is probably not responsible.

BSo the computer itself is the root cause, and ELAC 1 is definitely not serviceable now.

AWhich unit do we test first? Personally I say ELAC 1, because the readout names it directly.

BI completely agree. We isolate ELAC 1 first, and we send it for a thorough ground test.

AGood. If the ground test fails, we fit a serviceable ELAC and clear the fault message.

BFine. As soon as the replacement unit is fitted, I record the fault code and close the readout.

03Grammar in context — the zero conditional

A BITE message maps a fixed cause to a fixed indication, so the logic is permanently true. English expresses this with the zero conditional: the present tense in both parts. You state the condition, and you state the result that is always true. Examine these three lines taken directly from the dialogues.

“If the code starts with 34, the system is navigation.” — Dialogue 1
“If the self-test passes, the readout shows no fault found.” — Dialogue 1
“If the code has ATA 22, the system is autoflight.” — Dialogue 2

The rule is short, although many learners still apply it incorrectly. In the if-clause you use the present tense, and never will. In the result you also use the present tense, because the indication is always true, not merely once. So you correctly say “if the code starts with 34, the system is navigation”. The identical rule holds after when, as soon as and unless, because these clauses take the present tense too.

FunctionStructureExample
Code → system (fixed logic)If + present, + presentIf the code starts with 34, the system is navigation.
Test → standard resultIf + present, + presentIf the self-test passes, the readout shows no fault found.
Condition → instructionIf + present, + orderIf the reset does not clear it, isolate the unit.
Negative conditionIf + present negative, + presentIf the code does not clear, the LRU is suspect.

Three common mistakes (Latvian and Russian speakers)

✗ If the BITE will show 34, the system is navigation.
✓ If the BITE shows 34, the system is navigation.
Why: use the present tense in the if-clause, never will, although Latvian and Russian often use a future form here.
✗ If the self-test show a fault, the light comes on.
✓ If the self-test shows a fault, the light comes on.
Why: add -s for he/she/it in the present tense; Latvian and Russian speakers often drop it.
✗ If BITE shows fault code, technician reads it.
✓ If the BITE shows a fault code, the technician reads it.
Why: English needs articles; Latvian and Russian have none, so learners often drop the and a.

06Writing: a BITE fault-isolation log entry

Write a short log entry for the BITE fault, and use Simplified Technical English (ASD-STE100), because short sentences and approved words are easier to read on the line. Write one idea per sentence, keep every sentence under twenty words, and use the present tense in every if-clause, with no will.

Your task

Write 80–110 words to record the BITE fault. Give the fault code, the system, the suspect LRU, and the tests you ran. Use the zero conditional for the fixed logic, so you say clearly what the code means. State the follow-up action, and keep every sentence short.

Show model answer

TECH LOG ENTRY — BITE FAULT — ADIRU 1

Fault code: 34-12-34. If the code starts with 34, the system is navigation.

Fault message: ADIRU 1 FAULT. The suspect LRU is the number one air data unit.

Test 1: run the self-test. The self-test repeats the code, so the fault is confirmed.

Test 2: open the CMC. The CMC lists the same fault three times today.

Test 3: check the connector. The connector is clean and tight.

Result: ADIRU 1 is the suspect unit. Next step: run a ground test on ADIRU 1.

If the ground test fails, ADIRU 1 is not serviceable. Fit a serviceable unit.
