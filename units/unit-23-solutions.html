Loading and verifying avionics software — full answer key

CEFR B2E1–E8 with reasonsAnnotated writing modelTeacher / gated
This file is for the teacher (or for self-check after an honest attempt). Each answer carries a one-line reason, so it can be used to explain why, not only what. Accept any answer that means the same and is grammatically correct at B2 — the wording below is a model, not the only right form.

E1Gap-fill — one bank term per gap

Skill: vocabulary in context. Accept the exact term; mark the form, not the spelling of near-misses.

  1. dataloader — it is the tool that sends the software; you connect it to the port.
  2. checksum — a checksum error is the standard message for corrupted data.
  3. successful load — a finished bar only becomes this once BITE is green.
  4. configuration report — this is the screen that lists what the unit is really running.
  5. abort — to stop the load before it finishes when the bar freezes.
  6. task card — the job sheet that lists every reference to confirm.
  7. compatibility — the software runs on one hardware standard only, so this is checked first.
  8. tech log — the aircraft's running record; the result goes here before closing.
  9. LRU — a line-replaceable unit — the box that comes out with four bolts.
  10. power cycle — off then on again clears a temporary memory fault before a retry.

E3Dialogue completion — one word per gap

Skill: listening / register recall from the model dialogues.

  1. number — "software part number" is the fixed collocation.
  2. start — "clear to start" — begin the load once references agree.
  3. compatibility — "check compatibility" before loading.
  4. loader — the unit is talking to the (data)loader via the green link.
  5. abort — a frozen bar means abort this load first.
  6. cycle — "power cycle" — off then on again.
  7. BITE — the self-test the unit runs on itself.
  8. against — "cross-check the report against the task card."

E4Grammar transformation — once / when / as soon as

Skill: the grammar focus. The time clause takes the present tense — never will.

  1. Once the load finishes, run BITE. — present in the time clause; no "will finish".
  2. When the light turns green, press start. — trigger + present, then the imperative.
  3. As soon as it starts, watch the bar. — "as soon as" = the very next step.
  4. Once the software is loaded, verify the configuration. — keep the passive is loaded and the article the.
  5. When the BITE test passes, open the configuration report. — present passes, then the imperative.
  6. Once the load number is confirmed, start the data load. — passive gate, then the action.
  7. When the report matches the card, sign off the task card. — condition + present, then the imperative.
  8. As soon as the unit reboots, confirm no fault. — present reboots; the next step follows at once.

E5Reading 1 — Task card (AMM)

Skill: reading an authentic task card for facts. Short answers; accept with or without the article.

  1. the ground cart — the warning says power comes from the ground cart, never the battery.
  2. 285-A047 — Step 1 states the software part number on the media.
  3. mod 4 (or later) — Step 2 sets the minimum hardware standard.
  4. abort the load — Step 4: abort first when a checksum error appears.
  5. two — Step 4: quarantine the media after two consecutive failures.
  6. the tech log — Step 5: enter the result in the tech log.

E6Error-spotting — correct the underlined part

Skill: the three L1 interference errors (future in the time clause, dropped article, dropped passive be), plus agreement.

  1. finishes — present after when; drop "will".
  2. the configuration — put the missing article back.
  3. the software is loaded — restore the subject and the passive be.
  4. the dataloader — definite article: this specific loader.
  5. is — "checksum" is singular, so is, not are.
  6. is not a successful load — add the article a before the noun phrase.
  7. starts — present after "as soon as"; drop "will".
  8. in the tech log — definite article again: the tech log.

E7Reading 2 — Service Bulletin (SB)

Skill: reading an SB for facts and inference. Accept equivalents.

  1. the lost frequency after a power cycle — the Reason line: the radio loses the frequency after a power cycle.
  2. no (recommended) — "recommended, although not mandatory".
  3. mod 3 — Effectivity: mod 3 radios are incompatible.
  4. about one hour — Compliance: the task requires approximately one hour.
  5. 34-52-11-720 — Procedure: follow this task card.
  6. one year (twelve months) — Records: retain the old report for twelve months.

E8Listening review — Dialogue 3

Skill: detailed listening. Play "Verify and sign off" again; short answers.

  1. BITE — after 100%, the first check is the BITE self-test.
  2. the software part number (revision and load) — the configuration report lists these fields.
  3. the task card — A cross-checks the report against the card.
  4. 622-1140-001 — the LRU part number on the hardware line.
  5. mod 5 — the report's mod matches the physical unit.
  6. a power cycle — B power cycles once more to prove a reliable boot.
  7. yes — every field agrees, so verification is complete.
  8. in the tech log — the load number and result are recorded there.

WRITEWriting model — tech-log entry (Simplified Technical English)

Task: 60–90 words. Include the unit and part number, software part number and load number, the steps done, the BITE result, and the verification result, then name and date.

Model answer (annotated).

Comm radio No.2, LRU part number 622-1140-001, hardware mod 5. Loaded software part number 285-A047, revision C, load L-2231, per task card 34-52-11-720. The first load failed with a checksum error. I aborted the load and power cycled the loader. I loaded again with verified media. The second load was complete with no fault. BITE ran green. The configuration report matched the task card on every field. Verification complete. No faults found. — J. Ozols, 08 Aug 2026.
